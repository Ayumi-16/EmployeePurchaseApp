# 要件書 - Employee Purchase System

**作成日**: 2025年7月22日  
**バージョン**: 1.0  
**プロジェクト**: EmployeePurchaseApp

## はじめに

本文書は、社員証を利用したNFCログイン機能とQRコードを活用した商品購入システムを提供するiOSアプリケーションの要件を定義します。SwiftUIを用いたモダンなUI設計により、社内販売向けの直感的で使いやすいシステムを実現します。

## 要件

### 要件1: NFC社員証認証システム

**ユーザーストーリー**: 社員として、社員証をかざすだけで簡単にログインできるようにしたい。これにより、パスワード入力の手間を省き、迅速にシステムにアクセスできる。

#### 受け入れ基準

1. WHEN 社員がNFCスキャンボタンをタップ THEN システムはNFCリーダーセッションを開始する
2. WHEN 社員証がiPhoneに近づけられた THEN システムは社員IDを読み取り、社員マスタと照合する
3. WHEN 有効な社員証が検出された THEN システムは認証成功メッセージを表示し、QRスキャン画面に遷移する
4. WHEN 無効な社員証または未登録の社員証が検出された THEN システムはエラーメッセージを表示し、再スキャンを促す
5. WHEN NFCスキャンが20秒以内に完了しない THEN システムはタイムアウトエラーを表示する
6. WHEN 15分間無操作状態が続く THEN システムは自動的にログアウトし、ログイン画面に戻る

### 要件2: QRコード商品スキャン機能

**ユーザーストーリー**: 社員として、商品のQRコードをスキャンして商品情報を取得し、購入手続きを開始したい。これにより、商品情報の入力ミスを防ぎ、効率的に購入できる。

#### 受け入れ基準

1. WHEN ログイン後にQRスキャン画面が表示される THEN カメラビューとスキャンガイドが表示される
2. WHEN 有効な商品QRコードがスキャンされる THEN システムはJSON形式の商品情報を解析し、商品詳細を表示する
3. WHEN 無効なQRコードがスキャンされる THEN システムはエラーメッセージを表示し、再スキャンを促す
4. WHEN 商品情報が表示される THEN 商品名、価格、カテゴリ、ブランド、在庫数、サイズ選択肢が表示される
5. WHEN QRコードに必須フィールドが不足している THEN システムは「無効なQRコード」エラーを表示する

### 要件3: 商品選択・カート管理機能

**ユーザーストーリー**: 社員として、スキャンした商品のサイズや数量を選択し、複数商品をカートに追加して一括購入したい。これにより、まとめ買いが効率的に行える。

#### 受け入れ基準

1. WHEN 商品情報が表示される THEN サイズ選択、数量選択、「カートに追加」、「直接購入」ボタンが表示される
2. WHEN サイズが選択可能な商品の場合 THEN 利用可能なサイズオプションがボタンまたはピッカーで表示される
3. WHEN 数量が選択される THEN 在庫数を超えない範囲で数量を選択できる
4. WHEN 「カートに追加」がタップされる THEN 商品がカートに追加され、QRスキャン画面に戻る
5. WHEN カート内に商品がある THEN カートアイコンにバッジで商品数が表示される
6. WHEN カート画面が表示される THEN 追加された商品一覧、各商品の削除・数量変更機能が提供される
7. WHEN カート内商品の数量が変更される THEN 合計金額が自動的に再計算される

### 要件4: 決済・購入処理機能

**ユーザーストーリー**: 社員として、現金または給与天引きの支払い方法を選択して購入を完了したい。これにより、個人の支払い方法に応じて柔軟に購入できる。

#### 受け入れ基準

1. WHEN 「購入手続き」がタップされる THEN 支払い方法選択画面が表示される
2. WHEN 支払い方法が「現金」または「給与天引き」から選択される THEN 選択された方法がハイライト表示される
3. WHEN 「購入を確定」がタップされる THEN 購入データがCSVファイルに記録される
4. WHEN 購入処理が成功する THEN 購入完了画面が表示され、購入内容の詳細が確認できる
5. WHEN 購入処理が失敗する THEN エラーメッセージが表示され、再試行が可能である
6. WHEN 購入が完了する THEN カートが空になり、新しい購入を開始できる

### 要件5: データ管理・永続化機能

**ユーザーストーリー**: システム管理者として、社員マスタデータをCSVで管理し、購入履歴を自動的に記録したい。これにより、データの一元管理と購入実績の追跡が可能になる。

#### 受け入れ基準

1. WHEN アプリが起動される THEN システムはDocumentsフォルダ内のemployees.csvから社員マスタを読み込む
2. WHEN 社員マスタファイルが存在しない THEN システムは適切なエラーメッセージを表示する
3. WHEN 購入が完了する THEN 購入データがpurchases.csvに追記される
4. WHEN purchases.csvが存在しない THEN システムは自動的にヘッダー行付きのファイルを作成する
5. WHEN CSVファイルの読み書きでエラーが発生する THEN システムは適切なエラーメッセージを表示し、処理を中断する
6. WHEN 購入データが記録される THEN 購入日時、社員情報、商品情報、支払い方法、ステータスが含まれる

### 要件6: エラーハンドリング・ユーザビリティ

**ユーザーストーリー**: 社員として、システムエラーが発生した際に適切なガイダンスを受け、簡単に復旧できるようにしたい。これにより、システムの使いやすさと信頼性が向上する。

#### 受け入れ基準

1. WHEN NFCスキャンが失敗する THEN 「NFC読み取りに失敗しました」メッセージと再試行ボタンが表示される
2. WHEN QRコードスキャンが失敗する THEN 「QRコードが無効です」メッセージが表示され、自動的にスキャンが継続される
3. WHEN ネットワークエラーが発生する THEN 「ネットワークエラーが発生しました」メッセージが表示される
4. WHEN ファイル操作エラーが発生する THEN 具体的なエラー内容がユーザーに分かりやすく表示される
5. WHEN エラーが発生する THEN ユーザーは前の画面に戻るか、操作を再試行できる
6. WHEN 重要なエラーが発生する THEN アラートダイアログで表示され、軽微なエラーはトーストメッセージで表示される

## 非機能要件

### パフォーマンス要件

1. **応答時間**: UI操作に対する応答は200ms以内
2. **NFCスキャン**: 社員証検出から認証完了まで3秒以内
3. **QRスキャン**: QRコード検出から商品情報表示まで2秒以内
4. **メモリ使用量**: アプリのメモリ使用量は100MB以下を維持

### セキュリティ要件

1. **データ保護**: 個人情報を含むログ出力は禁止
2. **ファイル権限**: CSVファイルは適切なアクセス権限で保護
3. **セッション管理**: 15分間の無操作で自動ログアウト
4. **データ暗号化**: 要件なし（社内システムのため）

### 可用性・信頼性要件

1. **オフライン対応**: ネットワーク障害時も基本機能は動作継続
2. **データ整合性**: CSV書き込み時のデータ破損防止
3. **エラー回復**: システムエラー後の自動復旧機能
4. **バッテリー効率**: NFCスキャン時の電力消費最適化

### 保守性・拡張性要件

1. **コード品質**: 80%以上のテストカバレッジ
2. **アーキテクチャ**: MVVMパターンによる保守性確保
3. **国際化**: 日本語のみ対応（将来的な多言語対応を考慮した設計）
4. **アクセシビリティ**: 現時点では対応不要

## 制約条件

### 技術的制約

1. **対象OS**: iOS 15.0以上
2. **開発言語**: Swift 5.0以上
3. **UIフレームワーク**: SwiftUI
4. **NFC機能**: iPhone 7以降の実機でのみ動作
5. **カメラ機能**: QRコードスキャンにはカメラアクセス権限が必要

### リソース制約

1. **開発期間**: 要件に応じて段階的開発
2. **テスト環境**: NFC機能は実機でのみテスト可能
3. **データストレージ**: ローカルCSVファイルのみ使用
4. **ネットワーク**: オフライン動作が基本

### 運用制約

1. **データバックアップ**: 機能なし（要件により）
2. **ユーザー管理**: 社員マスタCSVによる管理
3. **商品マスタ**: QRコード内のJSONデータで管理
4. **決済処理**: 実際の決済は行わず、記録のみ

## 成功基準

1. **機能完成度**: 全要件の100%実装
2. **品質基準**: バグ発生率1%以下
3. **パフォーマンス**: 全非機能要件の達成
4. **ユーザビリティ**: エラー発生時の適切な案内表示
5. **保守性**: コードレビュー通過率100%
